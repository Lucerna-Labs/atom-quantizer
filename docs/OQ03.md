**OQ03 decoder and container contract**

OQ03 is the v0.2.4 research format. A record includes the complete decoder recipe. The main picker serializes a candidate, reads it through the record parser, decodes it, and measures those decoded values. The same decoder is used by file verification and GGUF export.

All integers and floats use little-endian storage. Lengths count bytes or elements as specified. CRC is CRC-64/ECMA-182, polynomial `0x42F0E1EBA9EA3693`, initial value 0, no reflection, final XOR 0. The check value for `123456789` is `0x6C40DF5F0B497347`. CRC detects accidental corruption; it is not authentication.

**Container header**

| Field | Encoding |
|---|---|
| Magic | Four bytes `OQ03` |
| Record count | u32 |
| GGUF prefix length | u64 |
| GGUF prefix | Exact source bytes through the aligned tensor-data start, excluding weights; may be empty for a generic tensor container |
| Header CRC | u64, covering all preceding header bytes |

The prefix preserves tokenizer and architecture metadata and the source tensor table. It counts toward the byte budget. Readers limit it to 256 MiB. Writers stage output in the destination directory, finalize the count and checksum, verify/decode the complete staged file, then publish without overwriting an existing destination.

**Record framing and payload**

Each record is `u64 payload_length | payload | u64 CRC`. The CRC covers the length and payload, excluding the CRC field itself. The complete frame is charged to the allocator.

| Payload field | Encoding |
|---|---|
| Name length and name | u32 bytes, followed by UTF-8 |
| Original GGML type | u32 |
| Dimension count | u8, from 1 through 8 |
| Dimensions | One u64 per axis, in GGUF order: innermost first |
| Inverse transform | u8: 0 = none, 1 = row Hadamard-8 |
| Row-norm count | u64; zero bypasses restoration |
| Row norms | f32 values |
| Payload kind | u8: 0 = block codec, 1 = exact F32 escape |

For block payloads, the remaining fields are:

| Field | Encoding |
|---|---|
| Element count | u64 |
| Strategy | u8: 0 = Q2, 1 = Q4, 2 = Q8 |
| Blind repair strength | f32 |
| Legacy packed-code tag | u64 |
| Packed-code integrity seed | u64 |
| Scale count and values | u64 count, then f32 values |
| Minimum count and values | u64 count, then f32 values; zero count denotes symmetric blocks |
| Packed length and codes | u64 byte length, then bytes |

For exact payloads, the remaining fields are `u64 element_count | f32 values`. Exact payloads require no inverse transform or norm restoration. Their values must already be representable in the final dense output dtype.

**Decode order**

For a block record: unpack/dequantize → stored blind repair → inverse transform → stored row-norm restoration → output storage rounding. F32/F16/BF16 original types imply their corresponding final rounding, returned to the caller as f32 values. Other original types produce f32 reconstructions in the tensor API. Thus a subsequent dense GGUF export does not add an unmeasured rounding step. F16 and BF16 rounding use round-to-nearest, ties-to-even.

All dimensions, code lengths, scale/minimum counts, transform eligibility, norm counts, finite metadata, and decoded values are validated. Names are unique. A reader rejects invalid checksums, truncation, unknown variants, inconsistent framing, and trailing data. Verification actually decodes every record.

`atom-quantizer decode model.oq --out new-model.gguf` reconstructs the model from the container alone. It requires a complete OQ03 container with stored model metadata and F32/F16/BF16 source storage types. K-quant sources remain readable/quantizable into OQ records, but K-quant GGUF writeback is unsupported. A limited tensor sample is a valid tensor container, not an exportable whole model.

**OQ02 compatibility**

OQ02 is read as a legacy stored representation, with code-only integrity. Its missing dimensions, inverse transforms, and norm corrections cannot be reconstructed from the file. The reader does not invent them, and whole-model GGUF export refuses an OQ02 file. Legacy numerical decode retains the original f32 behavior rather than retroactively applying OQ03 storage rounding. New writes always use OQ03.

**AC01 calibration format**

Calibration files use `AC01 | source_GGUF_SHA256[32] | corpus_SHA256[32] | u32 record_count | records | file_SHA256[32]`. The final SHA-256 covers all preceding bytes.

Each record contains `u32 name_length | UTF-8 name | u8 operator_kind | u32 sample_count`. Kind 0 then contains `u32 input_columns | sample_count × input_columns f32 values`; kind 1 contains `sample_count u32 token indices` for `token_embd.weight` lookups. Batches must be nonempty, linear inputs finite, and tensor names unique. The consumer checks source-file SHA-256 and operator shapes before encoding. A diagonal importance matrix is not accepted as a substitute for these input samples.
